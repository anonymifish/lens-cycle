# Lens Cycle 产品需求

## 1. 产品定位

Lens Cycle 是面向个人使用者的 Windows 11 本地桌面应用，用于统一管理眼部护理用品的
配置、采购库存、使用生命周期、护理事件、消耗预测和成本。产品强调离线可用、本地数据
所有权、库存可追溯和跨时间的使用记录，不依赖账户或云服务。

本应用不是医疗诊断或治疗工具，不替代专业医疗建议。

## 2. 范围

当前版本必须提供：

- 时间轴、库存、统计、设置四个主页面；
- 用品配置、产品、库存批次、地点、库存流水和使用实例的完整关系；
- 八类管理模板及各自的库存和生命周期行为；
- SQLite 本地持久化、当前格式备份恢复和数据位置移动；
- 失败回滚、退出前保存、重启反读和数据库完整性保护；
- Windows 11 x64 本地开发、测试和 Release 构建。

当前版本不包含账户、云同步、多人协作、移动端、Web 业务版或医疗建议。代码签名和应用
商店发布不属于仓库自动化范围。

## 3. 统一概念

```text
用品配置 ItemProfile
  └─ 产品 Product
       └─ 库存批次 StockLot
            └─ 库存流水 InventoryTransaction

用品配置 + 产品 + 来源批次
  └─ 使用实例 TimelineItem
       ├─ 状态区间
       ├─ 地点区间
       ├─ 眼别区间/复用周期
       ├─ 使用事实 UsageFact
       └─ 护理事件 LensCareEvent
```

- 用品配置描述“如何管理”；产品描述实际购买的品牌、型号和规格；
- 库存批次描述一次采购事实；库存流水描述数量或形态变化；
- 使用实例描述一个具体用品从启用到结束的生命周期；
- 计划、预测与实际事实必须分开保存和显示。

字段级定义见 [system_design.md](./system_design.md)。

## 4. 时间轴需求

- 时间轴必须跨年连续，不以自然年分页；
- 支持拖动空白区域平移、触控板水平移动和 `Ctrl + 滚轮`锚点缩放；
- 提供月、季度、半年、一年、全部记录和返回今天等快捷视图；
- 根据范围显示年、季度、月、周或日刻度，并避免标签重叠；
- 显示今天定位线，记住当前视窗和分组展开状态；
- 按镜片、周期更换用品、消耗品分组，同类重叠实例自动分配轨道；
- 支持搜索、状态筛选、分组折叠和详情查看；
- 区分使用中、当前暂停、历史暂停、已完成、计划/预测和护理事件；
- 允许启用、暂停、恢复、结束、重新打开、改期和确认拖动；
- 日期变更必须同步调整依赖区间、预测节点和相关事实，不产生非法重叠。

## 5. 用品配置、产品与地点

- 应用提供稳定的管理模板和标准类型；用户可以创建、编辑、排序、启用或停用用品配置；
- 产品必须选择一个启用的用品配置，并保持稳定 ID 关联和标准类型一致；
- 产品可以保存品牌、型号、规格、容量、包装数量、默认周期和排序；
- 地点可创建、编辑、停用和删除，至少保留一个启用地点；
- 仍被库存、流水或使用实例引用的地点、产品或配置不得直接删除；
- 名称变更不得切断历史关联。

## 6. 库存需求

- 支持首批入库和追加批次，保存批号、日期、有效期、地点、数量、价格和包装结构；
- 支持批次编辑、库存更正和跨地点转移；
- 可用库存必须由有效库存流水计算，不能保存不可追溯的独立余额；
- 已提交流水不可更新或删除；更正和撤销必须追加关联的反向流水；
- 作废未使用批次时保留批次与原始入库流水，追加反向流水并归档批次；
- 已经产生使用关系的批次不得按“未使用批次”作废；
- 删除误录使用事实或实例时，在同一事务中反向对应库存影响；
- 跨地点转移改变分地点数量但不改变全局总量；
- 任意时点余额都应能由流水重建，失败操作不得留下部分写入。

## 7. 八类管理模板

| 标识 | 名称 | 核心规则 |
| --- | --- | --- |
| `rigid_long_term` | 长期硬镜 | 眼别、启用/暂停/恢复/结束、复查和除蛋白事件；预计使用日按自然日计算 |
| `soft_daily` | 日抛软镜 | 完整盒开盒不立即减少片数；佩戴、损耗或丢弃时记录事实消耗；支持散片分配 |
| `soft_reusable` | 多天使用软镜 | 开盒后逐片启用，记录单片复用周期和下一片；删除首片误录不重新封盒 |
| `lens_case` | 镜盒 | 周期更换，左右眼区间独立累计且同一时点不能冲突 |
| `lens_accessory` | 镜片用品 | 按件启用和周期更换，不区分眼别 |
| `opened_container` | 开封瓶连续消耗 | 开封失效日与预计耗尽日分离；暂停延后耗尽预测但不延后失效日 |
| `discrete_dose` | 离散剂量消耗 | 每次事实按剂量扣减；护理事件确认后才产生相应消耗 |
| `batch_consumable` | 批次定量消耗 | 根据盘点、使用区间和速度预测；预测为零不自动写事实耗尽 |

## 8. 生命周期与事件

- 使用实例支持计划、使用中、暂停和完成状态；
- 暂停、恢复、结束和更正均保存用户确认的业务日期；
- 状态区间采用左闭右开，不能重叠，结束日不能早于启用日；
- 护理事件同时保留计划日期和实际完成日期，到期不等于完成；
- 佩戴、剂量、损耗和丢弃保存为可更正、可撤销的使用事实；
- 地点和眼别变化保存为历史区间，不用覆盖当前字段抹除历史；
- 预测由当前事实计算，不能修改已发生事实。

## 9. 统计需求

- 显示未来 90 天临期批次和低库存产品；
- 按时间范围统计购买支出、使用成本和损耗成本；
- 显示当前库存价值；
- 根据产品周期和历史消耗提供使用预测；
- 所有金额使用最小货币单位整数计算后格式化；
- 统计必须源于产品、批次、使用事实和库存流水，重启后结果一致。

## 10. 设置、备份与数据位置

- 保存时间轴语义色和预测参数，并即时应用；
- 设置写入失败时显示失败原因，界面不假装已经提交，并允许重试；
- 正常关闭前必须 flush 待保存设置；
- JSON 备份包含格式版本、应用版本、导出时间、业务数据、偏好和完整性校验；
- 恢复前验证大小、格式、版本、完整性和业务关系；失败不得覆盖当前数据库；
- 数据位置移动仅接受本机目录，先 checkpoint、复制和完整回读，再切换配置并重启；
- 迁移成功后保留旧数据库，由用户决定何时清理；
- 数据库异常时优先保留和隔离现场，并提供清晰的恢复入口。

## 11. 非功能需求

- 正式入口只能通过 Tauri 访问 SQLite；不得回退到浏览器存储或内存业务仓库；
- SQLite 写成功后才能更新 Store，组合操作必须具备事务原子性；
- 启用外键、WAL、完整同步、busy timeout 和启动健康检查；
- 支持最小窗口 `900 x 600`，常用 Windows 缩放比例下内容可用；
- 输入必须处理空值、边界日期、非法数量、断裂关联和重复提交；
- 本地开发和测试不得读取或复制真实用户数据库。

## 12. 完成判定

一个功能只有在以下条件同时满足时才算完成：

- UI 显示和成功/失败提示符合需求；
- Store 与 SQLite 的最终状态一致；
- 库存余额可由流水重建，历史流水保持不可变；
- 失败操作完整回滚；
- 退出并重启后能够反读相同结果；
- 相关自动测试、覆盖率门禁和桌面验收通过；
- 需求、设计和测试文档同步更新。
