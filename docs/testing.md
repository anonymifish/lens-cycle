# Lens Cycle 测试与验收

## 1. 测试目标

测试必须验证同一个业务动作在 UI、Zustand Store、SQLite、库存流水和重启反读之间一致，
而不是只验证组件能够渲染。失败路径必须证明 Store 未提交、数据库完整回滚。

## 2. 数据安全和隔离

- 所有文件型 Rust 测试和桌面测试必须设置 `LENS_CYCLE_DATA_DIR`；
- 目录必须位于本次 `artifacts/runs/<run-id>/data`；
- Vite 输出、覆盖率、Cargo target、日志和证据使用同一 Run 下的独立子目录；
- 不读取、修改、移动或删除真实应用数据；
- 不复制真实数据库或历史测试数据库作为 fixture；
- SQLite 可以只读查询核对，不能直接改库制造通过结果。

## 3. 自动门禁

`pnpm qa:all <run-id>` 依次执行：

1. Node.js/pnpm 环境版本门禁；
2. TypeScript typecheck；
3. ESLint；
4. Vitest 全量测试和覆盖率；
5. 单一存储架构门禁；
6. Rust fmt；
7. Rust clippy（warnings 视为错误）；
8. Rust 全量测试。

前端最低门槛：行覆盖率 90%，分支覆盖率 85%。业务源码修改后必须重新运行全量覆盖率；
不能只改测试来掩盖产品缺陷。

## 4. 测试分层

- 纯领域单元测试：日期区间、生命周期、预测、轨道、库存重建和数据完整性；
- React 组件/页面测试：交互、表单、提示、候选状态和错误状态；
- Rust 数据库测试：schema、约束、事务、备份恢复、迁移和不可变流水；
- 存储架构门禁：禁止重新引入浏览器持久化或绕过 SQLite；
- Release 桌面测试：真实进程、WebView2、SQLite、退出和重启闭环；
- 安装测试：MSI/NSIS 安装、启动、卸载和业务数据保留策略。

## 5. Release 桌面闭环

真实桌面测试至少覆盖：

- 首次和重复启动，正常关闭与关键写入后立即关闭；
- 用户偏好、地点、用品配置、产品、首批和追加库存；
- 批次编辑、库存页指定数量转移、时间轴实例携带原地点全部剩余库存转移、未使用批次
  作废和反向流水；
- 八类管理模板；
- 启用、使用、护理、暂停、恢复、结束、撤销、改期和误录删除；
- 八类管理模板详情均显示通用生命周期历史，支持暂停的品类可编辑当前及历史暂停区间，
  非硬镜详情不显示硬镜护理事件；
- 日抛、复用软镜、硬镜、护理液、开封瓶、离散剂量和批量耗材库存链路；
- 批量耗材结束时实际剩余必填且默认为空，分别验证盘亏、相等和盘盈；预测不写库存事实，
  撤销结束保留已确认的盘点更正，今天结束前后时间条宽度不跳变；
- 设置保存失败、重试、UI 状态和数据库回滚；
- 当前格式备份、恢复和数据位置移动；
- SQLite 最终数据、流水重建、不可变约束与重启反读。

每个关键场景统一断言：UI 提示正确、Store 与 SQLite 一致、流水可重建余额、历史流水不变、
失败完整回滚、退出重启后结果一致。

## 6. 169 项验收清单

机器可读的现行清单位于 [`tests/acceptance/cases-169.csv`](../tests/acceptance/cases-169.csv)，
共 169 项，涵盖视窗、布局交互、用品生命周期、设置、库存和桌面闭环。新增或改变业务规则
时，应同时更新需求、相关自动测试和该清单，避免维护第二份互相漂移的编号列表。

## 7. 缺陷与结果记录

- 记录环境、源码版本、Run ID、步骤、预期、实际和证据路径；
- 可稳定复现且符合现有规则的缺陷应修复，并先定向回归再运行全部门禁；
- 业务规则、数据含义或用户操作方式需要变化时先确认需求；
- 无法执行的桌面场景标记为未执行或阻塞，不推定通过；
- Release 修复后必须重新构建并验证受影响桌面流程；
- 当前可公开的基线结果记录在 [test_report.md](./test_report.md)。
