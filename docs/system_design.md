# Lens Cycle 系统设计

## 1. 领域结构

```text
用品配置 ItemProfile
  └─ 产品 Product
       └─ 库存批次 StockLot
            └─ 库存流水 InventoryTransaction

用品配置 + 产品 + 来源批次
  └─ 使用实例 TimelineItem
       ├─ 状态区间 StateInterval
       ├─ 地点区间 LocationInterval
       ├─ 眼别区间 / 复用周期
       ├─ 使用事实 UsageFact
       └─ 护理事件 LensCareEvent
```

管理模板和标准类型由应用提供稳定标识。用户管理用品配置与产品，但不能自由组合不兼容
能力。名称可以变化，历史关系必须依赖稳定 ID。

## 2. 数据不变量

- 产品必须关联用品配置，二者标准类型一致；
- 使用实例必须关联具体产品和来源批次；
- 可用库存只由有效流水重建，不能保存独立的权威余额；
- 已提交流水不可修改或删除，更正和撤销只追加关联流水；
- 预测库存、到期提示和计划事件不是事实；
- 多实体写入在一个 SQLite 事务中全部成功或全部回滚；
- 日期使用本地日历日 `YYYY-MM-DD`，区间使用左闭右开；
- 平均单位价格按 `1 元 = 10000` 保存为定点整数，金额事实不使用浮点数；
- 状态、地点和眼别历史区间不能产生非法重叠；
- 存在业务引用的地点、产品或配置不能物理删除。

## 3. 写入模型

地点、配置和产品等主数据使用独立命令。启用用品、记录消耗、完成护理事件、删除误录和
其他跨实体动作使用组合 mutation：

1. 前端领域函数从当前状态计算候选实体和新流水；
2. persistence gateway 将整个 mutation 发送给 Rust；
3. Rust 规范化字符串、ID、数量和日期并校验关系；
4. SQLite 在单事务中写入所有实体；
5. 成功后 Store 一次性应用候选状态；失败则 Store 不变并显示错误。

这套“提交后发布”模型保证 UI、Store、SQLite 和重启反读一致。

## 4. 库存账本

`StockLot` 保存采购日期、批号、有效期、地点、价格、单位和包装结构。
`InventoryTransaction` 保存入库、形态转换、散片分配、启用、消耗、转移、更正和反向记录。

- 转移同时保存来源地点、目标地点和数量，全局总量不变；
- 库存页由用户指定转移数量；时间轴活动实例移动地点时，数量取来源批次在实例原地点的
  当前全部余额，并与实例地点区间作为一个增量 mutation 提交；
- 日抛开盒只改变包装形态，实际佩戴/损耗时才减少事实片数；
- 多天软镜开盒后逐片启用，首片误录撤销不把盒子重新封装；
- 作废未使用批次时保留批次及原流水，追加逐笔反向流水并归档；
- 删除使用事实或误录实例时，追加库存反向流水并在同一事务中清理所属关系；
- SQLite 触发器阻止日常业务路径更新或删除历史流水。

平均单位价格最多输入 4 位小数并固定显示 4 位。库存价值和各类成本先以万分之一元整数
累计，只在最终人民币总金额展示处四舍五入到分，避免逐项提前舍入产生累计误差。

## 5. 生命周期

所有用品共享计划、使用中、暂停和完成等基础状态，但库存单位、周期和预测方式由八类
管理模板决定。暂停、恢复、结束、重新打开和改期都必须维护连续且不重叠的区间。
实例详情使用同一个生命周期历史视图呈现八类模板已有的启用、暂停、恢复和结束节点，
暂停编辑入口由实例的状态区间决定，不按模板名称限制。硬镜护理事件保持独立区域。

硬镜额外管理眼别和护理事件；日抛管理逐日佩戴与损耗；多天软镜管理盒内逐片周期；镜盒
管理眼别区间；开封瓶分离开封失效日和耗尽预测；离散剂量只在事实发生时扣减；批量耗材
使用中只生成预测，不自动写入耗尽事实。批量耗材结束时要求用户填写实际剩余数量，并将
它与来源批次在实例当前地点的账面余额比较：短缺追加损耗流水和损耗事实，盘盈追加更正
流水，相等则不追加库存流水。撤销结束恢复生命周期状态，但保留这次物理盘点及其库存
更正。完整要求见 [requirements.md](./requirements.md)。

## 6. 时间轴与预测

视窗坐标、缩放、刻度、轨道分配、日期区间、生命周期和预测计算集中在
`src/features/timeline/domain`。React 页面负责事件编排和呈现，避免把业务计算埋在 DOM
逻辑中。

实际事件和计划事件分别保存。预测可以随历史消耗、暂停区间、库存和设置变化重新计算，
但不得修改已经发生的使用事实或库存流水。

时间条也采用左闭右开区间。活动实例的显示终点为本地今天的下一日；用户选择某日结束时，
持久化的排他结束边界同样为该日的下一日，因此“今天结束”前后时间条宽度保持连续，而
详情仍显示用户选择的实际结束日。批量耗材使用中标为“预计剩余”，完成后标为“实际剩余”
或“实际库存”，避免把预测值解释为盘点事实。

## 7. 启动、错误与恢复

- 启动必须先完成数据位置解析、数据库打开、迁移、健康检查和快照加载；
- 初始化失败时停止进入业务页面；
- 偏好设置可防抖保存；正常退出或重启先建立写入屏障、等待在途写入并 flush 设置，再执行
  `wal_checkpoint(TRUNCATE)`、显式关闭连接，成功后才允许进程退出；
- checkpoint 返回 busy、保存失败或连接关闭失败时保持应用打开并显示具体阶段，允许重试；
- 窗口关闭、应用内退出、数据位置迁移重启和可拦截的 Tauri 正常退出统一使用该流程；
- WAL/SHM 只由 SQLite checkpoint、关闭和下次启动恢复处理，业务代码不得直接删除；
- SQLite 失败时不发布候选 Store 状态，并提供明确重试入口；
- 备份恢复先校验文件大小、版本、完整性和全部业务关系；
- 数据位置移动先 checkpoint、复制、建立 staging 数据库并完整回读；
- 替换或迁移失败时继续使用原数据库，旧数据库不会自动删除；
- 可隔离的数据损坏保留原文件并向用户显示恢复通知。

## 8. Schema 演进

可执行迁移位于 `src-tauri/migrations`。已经随正式版本分发的迁移不得改写；结构变化应
新增顺序迁移，同时更新 Rust 映射、数据库测试和设计文档。迁移测试必须创建新隔离数据库，
不得复制真实用户数据。

迁移 002 将旧版以“分”为比例、声明为 `REAL` 的 `stock_lots.unit_price_minor` 重建为
`INTEGER`，并将旧整数值乘以 100，统一表示万分之一元。迁移在事务中完成，旧两位小数
价格的人民币值保持不变；已经被旧版本截断的精度不作猜测，可在升级后手动编辑更正。
